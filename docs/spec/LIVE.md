# SPEC-LIVE — ファイル監視とライブ更新（基本仕様書）

担当 Issue: #8（初版）→ #31（Codex ライブ更新）

## ゴール

進行中のセッションをリロードなしで追えるようにする。

## できること

- セッション分析画面を開いている間、そのセッションのログに追記があると、リロードせずに新しいメッセージが会話の末尾へ自動で現れる
- 追記に合わせて、ヘッダの集計（総トークン・推定コスト）とやりとり別コストグラフも更新される
- ヘッダに**ライブ状態**を表示する（接続中 / 切断）。サーバとの接続が切れたら自動で再接続を試み、再接続できたら取りこぼし分をまとめて反映する
- 更新されるのは**開いているセッションだけ**。別のセッションに追記があっても、表示中の画面は再描画されない
- 監視対象のファイルが一時的に読めなくても（書き込み中・削除・権限エラー）、サーバは落ちずに監視を続ける
- 監視はサーバ起動中つねに動作し、新しく作られたセッションファイルも監視対象に自動で入る

## 対象外（このスペックでは扱わない）

- 一覧画面（Overview・プロジェクト・ダッシュボード）のライブ更新。これらは従来どおり画面を開いたときに最新を取得する
- ~~Codex CLI ログの監視~~（Issue #31 で対応。下のセクション参照）

## 自動検証（E2E・Issue #10）

合成ログを読み込ませたサーバに対し、Playwright で以下を自動検証する。

- セッション分析画面を開いた状態で合成 JSONL に追記すると、リロードなしで新しいメッセージが会話の末尾へ現れる
- 追記に合わせてヘッダの総トークン・推定コストが増える
- 別のセッションを開いた状態では、他セッションへの追記で表示中の画面が変わらない

サーバ再起動をまたぐ切断・再接続の確認は自動化せず、オーナー確認方法に残す。

## オーナー確認方法

1. `npm run serve` でサーバを起動し、ブラウザで進行中のセッション（この会話自身でよい）のセッション分析画面を開く
2. Claude Code でそのセッションの会話を続ける
3. リロードせずに新しいメッセージが会話の末尾へ表示されることを確認する
4. ヘッダの総トークン・推定コストが追記に合わせて増えることを確認する
5. 別のセッションを開いた状態では、進行中セッションへの追記で画面が変わらないことを確認する
6. サーバを再起動（または停止→起動）し、画面がライブ状態の変化（切断→再接続）を表示し、再接続後に追従が再開することを確認する

実装方針・受け入れ基準は [docs/design/LIVE.md](../design/LIVE.md)。

# Codex ライブ更新（Issue #31）

## ゴール

進行中の Codex セッションも、Claude セッションと同じようにリロードなしで追えるようにする。

## できること

- **Codex rollout の追記に追随する**: Codex のセッション分析画面を開いている間、rollout に追記があるとリロードなしで新しいメッセージが末尾へ現れ、追随の仕組み（接続状態表示・再接続・取りこぼし反映）は Claude セッションと共通で働く
- **新しいセッション・新しい日付ディレクトリも自動で監視対象に入る**: `~/.codex/sessions/YYYY/MM/DD/` の新規日付ディレクトリ・新規 rollout ファイルは、サーバ再起動なしで監視対象に入る
- **Codex セッションを開いてもインデックスが壊れない**: ライブ更新の再解析が Codex の正規化で行われる。現状はライブ購読の再解析が Claude 前提で走るため、Codex セッションを開くと壊れたインデックスがキャッシュに残る不具合がある（本 Issue で修正）。既に壊れたキャッシュが残っている場合も、正しい内容へ自動で作り直される
- ライブ対象は従来どおり**セッション分析画面のみ**（一覧画面のライブ更新はしない）

## 自動検証（E2E）

- Codex 合成 rollout のセッション分析画面を開いた状態で追記すると、リロードなしで新しいメッセージが末尾へ現れる
- 別セッションを開いた状態では、Codex rollout への追記で表示中の画面が変わらない

## オーナー確認方法

1. サーバを起動し、進行中の Codex セッション（Codex CLI で会話を続けるもの）のセッション分析画面を開く
2. Codex CLI で会話を続け、リロードなしで新しいメッセージが末尾へ表示されることを確認する
3. 新しい日付（翌日など）や新規セッションが、サーバ再起動なしで一覧取得時に現れることを確認する
4. Codex セッションを開いた後も、そのセッションの表示が壊れない（再読込しても正しく表示される）ことを確認する
