# SPEC-CHAT — セッション分析・チャットビューア（基本仕様書）

担当 Issue: #6・#40・#52

画面イメージの正本: [docs/mockups/viewer-mock.html](../mockups/viewer-mock.html)（2026-08 のモック合意で確定）

## ゴール

会話を読みやすく整形して表示し、どのやりとりで何（モデル・ツール・MCP・エージェント・スキル）が使われ、いくら掛かったかを追えるようにする。

## できること

- セッション分析画面はプロジェクト画面からのドリルダウンで開く（独立したセッション一覧画面は持たない）。パンくず `← Overview / <プロジェクト> / <セッション>` で戻れる
  - Overview・プロジェクト画面の本実装は SPEC-DASH（#7）。#6 では到達手段として**仮の簡易一覧**（プロジェクト → セッション）だけを置き、#7 で置き換える
  - プロジェクトはログのディレクトリ名（`/` が `-` に変換された形式）ではなく、**ユーザーが普段目にする実パス**（例 `/Users/…/agent_viewer`）で表示する。実パスはセッションログの cwd から得る（変換は不可逆なため復号しない）
  - セッションを 1 件も持たないプロジェクト（永続メモリ `memory/` だけのディレクトリ等）は**既定で一覧に出さない**。「セッション 0 件も表示」のチェックボックスで表示できる
- ヘッダにセッションの集計（モデル・総トークン・推定コスト・ライブ状態・破損スキップ行数）を表示
- **compaction（コンテキスト圧縮）の発生がわかる**（Issue #52）。判定は会話内の compact 区切り表示と同じ（Claude Code の `compact_boundary`）
  - **やりとり別コスト棒グラフ**: compaction が発生した位置にアイコン（⚡）のマーカーを表示する。マーカーの本数 = セッション内の発生回数。マーカーにカーソルを載せると tooltip で「compaction #N 発生」の説明が出る
  - **会話（チャット欄）**: 既存の compact 区切り線に通し番号を付けて目立たせる（例「⚡ compaction #1 — 以前の会話を要約」）。区切り線の本数・番号はグラフのマーカーおよびセッション一覧の回数と一致する
  - セッション一覧（プロジェクト画面）での回数列は [docs/spec/DASH.md](DASH.md) 側に記載
  - Codex セッションでは表示されない: 実ログ調査（2026-08-13・25 ファイル・全行走査）で compaction 相当のイベント type が未観測（token_count 累積の減少も 0/804 行）のため、発生の検出自体ができない（調査記録は [docs/design/CODEX.md](../design/CODEX.md)）
- **このセッションの利用状況**: ツール別ランキング、MCP サーバ / subagent / Skill の一覧
- **やりとり別コスト棒グラフ**: ユーザー入力 1 回を 1 やりとりとし、AI 応答と subagent のコストを合算した推定値を棒で表示する。縦帯クリックでそのやりとり（ユーザー入力 + AI 応答一式）だけに会話を絞り込む。compact で要約済みのやりとりはグレー表示・クリック不可とし、コスト合計の整合は保つ
- 会話はメイン領域の**横幅 100%** で表示
- 長いセッションでも、下へスクロールすると後続のメッセージが順次描画され、**会話の最後まで読める**（スクロールしても空白にならない）
- **種別チップ**: 会話内の使用箇所を色ドット + ラベルで明示する（model / tool / MCP / agent / skill）。MCP は `mcp__<server>__<tool>` をサーバ名・ツール名に分解して表示。冒頭に凡例を置く
- ツール呼び出しと実行結果は折りたたみ表示。失敗（is_error / exit code）は明示する
- compact やターン区切りを会話の区切りとして表示
- sidechain / subagent は分岐として展開でき、使用モデルとコストを表示
- メッセージ単位のトークン数（キャッシュ内訳含む）と推定コストを表示
- 全セッション横断の全文検索（入口は Overview）。検索のサーバ側（ストリーム grep）は SPEC-API（#5）で実装済みで、**検索 UI は入口を持つ Overview と合わせて SPEC-DASH（#7）で提供する**

## 自動検証（E2E・Issue #10）

合成ログ（匿名化フィクスチャ）を読み込ませたサーバに対し、Playwright で以下を自動検証する。実ログには触れない。

- Overview → プロジェクト → セッション分析へたどり着き、パンくずで戻れる
- ヘッダにモデル・総トークン・推定コスト・破損スキップ行数（壊れた JSON 行の件数）が表示される
- ツール呼び出しが折りたたまれ、開くと入出力が読める。失敗が明示される
- やりとり別コスト棒グラフの縦帯クリックで会話が絞り込まれ、解除できる
- 巨大行（50KB 超）を含むセッションでも画面が表示される
- 画面に収まらない行数のセッションで、メイン領域を末尾までスクロールすると最後のメッセージが表示される（Issue #40）

## オーナー確認方法

ブラウザで `http://127.0.0.1:4517` を開き、実ログのセッションを表示して以下を目視確認する。

1. 簡易一覧からプロジェクト → セッションとたどってセッション分析画面が開き、パンくずで戻れる
2. ヘッダにモデル・総トークン・推定コスト・破損スキップ行数が出る
   - compaction が起きたセッションでは、やりとり別コスト棒グラフに ⚡ マーカーが発生位置に出て、会話内の compact 区切り線（通し番号付き）の本数と一致する。Codex セッションでは出ない
3. ツール呼び出しが折りたたまれ、開くと入出力が読める。失敗が赤く明示される
4. compact・ターン区切りが会話の区切りとして表示される
5. sidechain / subagent が分岐として展開でき、モデルとコストが見える
6. メッセージ単位のトークン内訳（キャッシュ含む）と推定コストが出る
7. やりとり別コスト棒グラフの縦帯クリックで会話が絞り込まれ、解除できる
8. 数千メッセージのセッション（実ログ最大 約 69MB）でもスクロールが引っかからず、**下までスクロールすると会話の最後のメッセージまで表示される**（途中から空白にならない）

実装方針・受け入れ基準は [docs/design/CHAT.md](../design/CHAT.md)。
