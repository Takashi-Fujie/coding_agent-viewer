# SPEC-CONFIG — 設定・定義の可視化（基本仕様書）

担当 Issue: #9

## ゴール

`~/.claude/` 配下の設定・定義（エージェント・スキル・プラグイン・settings・プロンプト履歴）を読み取り、セッションログの起動実績と突き合わせて「定義したのに使っていないもの」を見つけられるようにする。

## できること

### 定義の一覧表示

- **エージェント定義**（`agents/*.md`）を一覧表示する。各定義の frontmatter から名前・説明・使用ツール・モデルを読み取って表示する
- **スキル定義**（`skills/<name>/SKILL.md`）を一覧表示し、frontmatter の説明を表示する
- **プラグイン**はインストール記録（`installed_plugins.json`）に基づいて、プラグイン名とマーケットプレイスを一覧表示する（ディレクトリ名の羅列ではなく、実際にインストールされているものを出す）
- frontmatter が無い・壊れている定義ファイルがあっても画面全体は落とさず、その定義は「パース不能」として一覧に残す

### settings の可視化

- `settings.json` の **hooks / permissions / enabledPlugins / statusLine** を画面に表示する
- hooks はイベント別に何が登録されているかを表示する
- permissions は allow / deny / ask のルール実値をそのまま一覧表示する（ローカル専用画面のため）

### プロンプト履歴

- `history.jsonl` を読み取り、**プロジェクト別のプロンプト数と最終利用日時**を表示する
- セッションログ（`projects/`）に無いプロジェクトの履歴も表示される（history.jsonl のほうが古い記録を含むため）
- 壊れた行はスキップして継続する

### 定義と起動実績の突き合わせ（未使用検出）

- エージェント定義・スキル定義それぞれについて、全セッションの起動実績（Agent ツールの subagent_type / Skill ツールの skill）と突き合わせ、**総起動回数と最終起動日時を併記**する
- **定義があるのに起動実績が全期間で 0 件のものを「未使用」として目立たせる**。最近使っていないだけの定義は最終起動日時で判断できるようにする
- 逆（起動実績はあるが `~/.claude/` に定義が無い）は異常扱いしない。ビルトインエージェント（general-purpose 等）・プロジェクト固有定義・プラグイン由来スキルが正常に該当するため
- 突き合わせは名前の一致で行う。プラグイン由来スキルの起動名は `プラグイン名:スキル名` 形式なので、ユーザー定義スキル（プレフィックス無し）とは別物として扱う

## 対象外（このスペックでは扱わない）

- プロジェクト側（各リポジトリの `.claude/`）の定義スキャン。定義の正本が各リポジトリにあり、`~/.claude/` の走査では見えないため
- 定義ファイル本文の編集機能（表示のみ）
- Codex CLI の設定（`~/.codex/config.toml` 等）。Issue #31 のソース切替（SPEC-DASH 側）でも設定・定義画面は**対象外**とする — この画面は Claude Code の設定を表示する画面であり、source filter の切替は効かせない。Codex 設定の可視化は必要になったら別 Issue を起こす

## 表示上の約束

- `settings.json` の permissions 実値・プロンプト履歴の本文は**画面に出すが Spec・Issue・PR には転記しない**（public リポジトリのため）
- 動作確認の証跡も同様に、**件数などの数値要約のみ**を PR / Issue に記録する（スクリーンショットは permissions 実値やプロンプト本文を含むため貼らない）

## 自動検証（E2E・Issue #10）

合成の `~/.claude` 相当ディレクトリ（匿名化したエージェント・スキル・プラグイン記録・settings・履歴）を読み込ませたサーバに対し、Playwright で以下を自動検証する。実際の `~/.claude` には触れない。

- 設定・定義画面にエージェント・スキル・プラグインの一覧が表示される
- frontmatter が壊れた定義が「パース不能」として一覧に残る（画面全体が落ちない）
- 起動実績が 0 件の定義が「未使用」として表示される

## オーナー確認方法

1. `npm run serve` でサーバを起動し、設定画面を開く
2. エージェント一覧が自分の `~/.claude/agents/` のファイル一覧と一致し、各定義のモデル・ツールが frontmatter と一致することを確認する
3. スキル・プラグイン一覧が実際のインストール状況と一致することを確認する
4. hooks / permissions / enabledPlugins / statusLine が自分の `settings.json` の内容と一致することを確認する
5. プロンプト履歴のプロジェクト一覧に、`projects/` に無い古いプロジェクトが含まれることを確認する
6. 使っていないエージェント・スキルが「未使用」として表示され、実感と一致することを確認する

実装方針・受け入れ基準は [docs/design/CONFIG.md](../design/CONFIG.md)。
