# SPEC-DASH — ダッシュボード（基本仕様書）

担当 Issue: #7（初版）→ #31（ソース切替・Codex 統合）→ #41（worktree グルーピング表示）→ #49（同一プロジェクトの Claude / Codex 表示統合）

画面イメージの正本: [docs/mockups/viewer-mock.html](../mockups/viewer-mock.html)（2026-08 のモック合意で確定）

## ゴール

**Overview → プロジェクト → セッション**の 3 階層ドリルダウンで、全体俯瞰から気になる作業へ一直線に降りられるようにする。ナビは「Overview / Tools & Agents / 設定・定義」の 3 項目のみとし、プロジェクト画面・セッション分析画面はドリルダウンで到達する（パンくずで戻る）。

## できること

1. **Overview** — 期間フィルタ（今日 / 7日 / 30日 / 90日 / 月初来）、総コスト（推定）、総トークン、モデル別利用状況のドーナツ 2 つ（トークン / コスト）、日次トークン積み上げ + コスト折れ線、プロジェクト一覧（集約せず全件表示・並び替え付き）、モデル別内訳テーブル
2. **プロジェクト画面** — 日次モデル別トークン積み上げ + コスト折れ線、セッション一覧（並び替え付き）
3. **Tools & Agents** — ツール別ランキング、失敗率（tool_result のエラーから算出）、プロジェクト別ツール利用、MCP サーバ別内訳、hook 発火履歴、エージェント定義 × 起動実績（未使用検出）、Skill 呼び出し履歴（最終使用日時付き）

### 全文検索（Issue #10 で追加）

- Overview に検索ボックスを置く。語を入力すると全セッション横断の全文検索（#5 のストリーム grep API）を実行し、ヒット一覧（プロジェクト・セッション・該当行の抜粋）を表示する
- ヒットをクリックするとそのセッションのセッション分析画面へ遷移する
- ヒット 0 件のときは「該当なし」を明示する

### この Issue で扱わないもの（#7 時点）

- **subagent 実行トレースのツリー表示** — セッション分析画面（#6 実装済）の sidechain インライン表示と内容が重複するため置かない。Tools & Agents には subagent 別の起動回数集計のみ置く（2026-08-06 合意）
- **プロジェクト一覧の「その他」集約行** — モックにはあるが、集約せず全件表示とする（2026-08-06 合意）
- 設定・定義画面（#9）、ライブ更新バッジ（#8）、全文検索ボックスの結線（検索 API は #5 済・画面統合は本 Issue の任意項目）

## 表示上の約束

- **チャートの共通操作**: チャートの縦帯（1 日 = 1 帯）クリックで、直下の一覧をその日に対応する項目だけに絞り込む。Overview では日付 → プロジェクト、プロジェクト画面では日付 → セッション。選択帯はハイライトし、解除チップを表示する。再クリックでも解除できる。活動が無い日は「該当なし」を明示する
- **トークンとコストは二軸グラフにしない**。x 軸（日付）を共有した上下 2 パネル（上: 積み上げ棒、下: コスト折れ線）で並べる
- Overview の積み上げは**トークン種別**（input / output / cache write / cache read）、プロジェクト画面の積み上げは**モデル別**。モデルの色はドーナツ・積み上げで共通の固定割り当てとする
- コストは常に「推定」と明示し、キャッシュ内訳を必ず表示する（SPEC-COST の表示上の約束）
- **未知モデルは警告バナー**で件数と「コストに含まれていない」ことを明示する（0 円扱いで黙らせない）
- **日次集計はローカル日付**で丸める（ブラウザのタイムゾーンオフセットをサーバへ渡して集計する。UTC のままだと JST では朝 9 時まで「今日」が空になるため。2026-08-06 合意）
- 設計基準幅は MacBook Pro 14 インチの論理解像度 **1512px を最小**とし、それ未満は縮めず横スクロールで比率を保つ

## ナビゲーション

左ナビは「Overview / Tools & Agents」の 2 項目で始める（「設定・定義」は #9 で追加）。Overview を起点（`#/`）とし、プロジェクト画面・セッション分析画面はドリルダウン（パンくずで戻る）。既存のプロジェクト一覧（#6 の起点画面）は Overview に置き換わる。

## 自動検証（E2E・Issue #10）

合成ログを読み込ませたサーバに対し、Playwright で以下を自動検証する。

- Overview に総コスト（推定）・総トークン・プロジェクト一覧が表示され、合成ログの内容と一致する
- Overview の全文検索で合成ログ内の語を検索でき、ヒットからセッション分析画面へ遷移できる
- Tools & Agents にツール別ランキングが表示される
- 未知モデルを含むログで警告バナーに件数が表示される（0 円扱いで黙らせない）

## オーナー確認方法

実ログを読み込んだ状態で画面をレンダリングし、以下を目視確認する:

1. Overview の総コスト・総トークンが `npm run report` の数値と一致する
2. 期間プリセット切替とチャートの日付クリック絞り込み（選択チップ・解除・該当なし表示）が動く
3. Overview → プロジェクト → セッション分析へドリルダウンし、パンくずで戻れる
4. Tools & Agents の失敗率・MCP 内訳・未使用エージェント検出・hook 発火履歴が実ログの内容と整合する

実装方針・受け入れ基準は [docs/design/DASH.md](../design/DASH.md)。

# ソース切替と Codex 統合（Issue #31）

## ゴール

Claude と Codex のログが混在しても、**どの行がどのソースか一目で分かり、ソースを絞って眺められる**ようにする。Claude だけを使っている人の画面は今までと何も変わらない。

## できること

### ソース切替（source filter）

- **「全ソース / Claude / Codex」** の切替を各画面の期間フィルタ横に置く（Overview・Tools & Agents。2026-08-09 オーナー合意で左ナビから移動）。選択状態は画面間で共通に保持され、Overview（合計値・チャート・プロジェクト一覧・モデル内訳）、プロジェクト画面、Tools & Agents、全文検索のすべてに効く
- 絞り込みは**サーバ側で行う**。合計値やチャートも選んだソースだけの数値になる（画面側で行を隠すだけの見せかけにしない）
- 既定は**全ソース**。選択は画面遷移をまたいで保持される
- 切替 UI は**常時表示**する。Codex のセッションが 1 件も無い環境では「Codex」の選択肢を**無効（disabled）**にする（2026-08-09 オーナー合意）。「Claude 単独利用者の既存 UX を壊さない」とは、既定（全ソース）のままなら一覧・数値・操作が従来と同一であること

### ソースの識別表示

- プロジェクト一覧・セッション一覧・検索ヒット・パンくずの各行に**ソースバッジ**（Claude / Codex）を付ける
- **Codex グループの行ラベルは日付（グループ ID）を主とし、cwd 由来のラベルにしない**。現状は行ラベルが cwd 末尾になり Claude プロジェクトと見分けが付かないため（Issue #31 コメントで合意した受け入れ軸）
- Claude セッションの行ラベル・並び順は従来と同一

### usage 未集計のセッションを消さない

- Codex のトークン・コストは #30 まで未集計（構造的に 0）。**0 でもソースとして識別・表示できること**を基準にする
- **チャートの日付クリック絞り込みで、usage が 0 でもその日に活動（レコード）があるプロジェクト / セッションは一覧に残す**。現状は totalTokens > 0 または estimatedCost > 0 で除外しており、Codex 分が日別絞り込みから全て消える（Issue #31 コメントで合意した受け入れ軸）。その日にレコードが無いものは従来どおり出さない
- Codex 行のコスト・トークン欄は「0 円」と断定せず**未集計であることが分かる表示**にする（0 円扱いで黙らせない、の SPEC-COST 方針に合わせる）

## やらないこと・制限

- Codex の usage・コスト集計そのもの（#30）。本 Issue は「未集計でも壊れない・消えない・識別できる」まで
- 一覧画面のライブ更新（従来どおり画面を開いたときに最新を取得。ライブ対象はセッション分析画面のみ — SPEC-LIVE 側）
- Tools & Agents の Codex 向け意味論の最適化（Codex のツール集計は現状の toolUses ベースのまま統合表示する）

## 自動検証（E2E）

Codex 合成フィクスチャを読み込ませたサーバに対し、Playwright で以下を自動検証する（E2E サーバへの Codex ソース登録・フィクスチャ seed も本 Issue の範囲）。

- 切替 UI が表示され、「Codex」を選ぶと Overview の一覧が Codex グループだけになり、合計値が変わる
- 「Claude」を選ぶと Codex グループが消え、Claude のみの従来値と一致する
- Codex グループの行にソースバッジと日付ラベルが表示される
- 日付クリック絞り込みで usage 0 の Codex セッションが一覧に残る
- Codex セッションが無い seed では「Codex」の選択肢が無効（disabled）表示になる

## オーナー確認方法

1. 実ログ（Claude + Codex 両方あり）でサーバを起動し、切替 UI で 3 状態を切り替えて、一覧・合計値・チャートが連動することを確認する
2. Codex グループが日付ラベル + バッジで表示され、Claude プロジェクトと見分けが付くことを確認する
3. Overview の日付クリックで、その日に使った Codex セッションが（usage 0 でも）一覧に残ることを確認する
4. 全ソース選択時の合計値が従来（切替導入前）と一致することを確認する

# worktree グルーピング表示（Issue #41）

## ゴール

worktree セッションが本体プロジェクトへ統合された後（SPEC-CORE の Issue #41）、プロジェクト詳細画面で**どのセッションがどの worktree の作業か**が一目で分かるようにする。統合で情報を落とさない。

## できること

### プロジェクト一覧（Overview）

- worktree のプロジェクト行が消え、本体プロジェクトの行に統合される。セッション数・トークン・コスト・レコード数は worktree 分を合算した値になる
- 統合されたプロジェクト行の見た目（ラベル・パス表示）は本体プロジェクトの従来表示と同じ

### プロジェクト詳細（セッション一覧）

- セッション一覧を **worktree ごとのグループに分けて表示する**。「本体」グループと各 worktree のグループ（worktree 名をラベルにする）に分かれ、各グループにセッション件数を添える
- グループ内の並び順は従来どおり（最終更新の新しい順）。グループの並びは「本体が先頭、worktree は最終更新の新しい順」とする
- worktree セッションが 1 件も無いプロジェクトでは、グループ見出しを出さず従来と同じ見た目にする（worktree を使わない利用者の画面は変わらない）
- 日次チャート・合計値はプロジェクト全体（本体 + 全 worktree）の値。日付クリック絞り込みもグループ表示を保ったまま効く

## やらないこと・制限

- worktree 単位での集計チャート・フィルタ（グルーピング表示まで。worktree 別の日次チャート等はやらない）
- セッション分析画面（SPEC-CHAT）の変更は無し

## オーナー確認方法

1. worktree セッションを含む実ログでプロジェクト詳細を開き、「本体」と worktree 名のグループにセッションが分かれて表示されることを確認する
2. worktree の無いプロジェクトでは従来と同じ見た目（グループ見出し無し）であることを確認する
3. 日付クリック絞り込みでグループ表示が保たれることを確認する

# 同一プロジェクトの Claude / Codex 表示統合（Issue #49）

統合の判定・id 規約は [docs/spec/CORE.md](CORE.md) の同名セクション。本セクションは画面・フィルタ・集計内訳の見え方を定める。

## ゴール

同じディレクトリで Claude Code と Codex を併用している場合、プロジェクト一覧・プロジェクト詳細で **1 つのプロジェクトとして俯瞰できる**ようにする。片方のソースしか使っていないプロジェクトの見た目は変わらない。

## できること

### プロジェクト一覧（Overview）

- 同一の本体ルートを持つ Claude / Codex のプロジェクト行が **1 行に統合される**。セッション数・トークン・コスト・レコード数は両ソースの**合算値**になる
- 統合行には**両方のソースバッジ**（Claude / Codex）を付ける。単一ソースのプロジェクト行は従来どおり 1 つのバッジ
- 行ラベル・パス表示は従来どおり（cwd 末尾の basename + フルパスのサブテキスト）

### プロジェクト詳細

- セッション一覧に**両ソースのセッションが並ぶ**。各行のソースバッジは従来どおり（どの行がどのソースかは行単位で識別できる）
- グループ分けの軸は従来どおり **worktree のみ**（「本体」/ worktree 名）。ソースで入れ子にはしない。グループ内の並びも従来どおり最終更新の新しい順（ソース不問で時系列に混ざる）
- ヘッダの合計値（セッション数・トークン・コスト）は両ソースの合算。**ソース別の内訳を添えて表示する**（例: セッション数 12 のうち Claude 8 / Codex 4 が分かる）
- 日次チャートは両ソース合算のモデル別積み上げ + コスト折れ線（Codex のモデルも同じチャートに系列として現れる。ソース別の系列分割はしない）

### ソース切替との関係（部分表示）

- ソース切替（全ソース / Claude / Codex）で統合プロジェクトの**行は残り、値だけが選択ソース分になる**（部分表示）。選択ソースにセッションが 1 件も無いプロジェクト行は従来どおり一覧から消える
- プロジェクト詳細もソース切替に追従する（選択ソースのセッション・集計だけになる。統合 id のまま URL は変わらない）

### 全文検索・Tools & Agents

- 検索ヒット・Tools & Agents のプロジェクト別集計は統合プロジェクト id で表示する（ヒット行のソースバッジは従来どおり）

## やらないこと・制限

- ソース別の日次チャート系列・ソース別チャートの並置（内訳はヘッダの数値まで）
- セッション分析画面（SPEC-CHAT）の変更は無し
- Codex の未集計表示（トークン 0 のセッション）の扱いは従来どおり（SPEC-DASH-089）

## 既存仕様の改定（#49）

- **SPEC-DASH-081〜085・090（ソース切替）**: 「選択ソースだけのグループになる（他ソースのグループが消える）」→ 統合プロジェクトは行が残って値が部分表示になる。選択ソースにセッションが無いプロジェクトだけが消える
- **SPEC-CODEX-100〜105（`codex:` グループ id）**: グループはソース別のまま維持し、グループ id は接頭辞なしのパス縮約に変わる（一意キーは id + ソース。同一 id の Claude / Codex グループが表示層で 1 行になる）。`codex:` 付き URL は 404
- **SPEC-CODEX-105 の「同じ本体ルートの claude グループとは併合されない」**: データモデル上は真のまま（1 グループ 1 ソース維持）。表示層でのみ統合される

## 自動検証（E2E）

Claude + Codex 両ソースの合成フィクスチャ（同一 cwd）を読み込ませたサーバに対し、Playwright で以下を自動検証する。

- 同一 cwd の Claude / Codex グループがプロジェクト一覧で 1 行になり、合算値と両ソースバッジが表示される
- 統合プロジェクトの詳細に両ソースのセッションが表示され、各行にソースバッジが付く
- ソース切替（Claude / Codex）で統合行が残り、値が選択ソース分になる
- `codex:` 付き旧 URL へのアクセスが 404 になる

## オーナー確認方法

1. Claude と Codex の両方で作業した実プロジェクト（agent_viewer 等）が一覧で 1 行になり、セッション数・トークン・コストが両ソースの合算であることを確認する
2. プロジェクト詳細で両ソースのセッションが時系列に混ざって表示され、ソースバッジ・worktree グループ表示が保たれていることを確認する
3. ソース切替で行が消えずに値が切り替わること、Codex しか使っていないプロジェクトは Claude 選択で消えることを確認する
4. 全ソース選択時の Overview 合計値が統合前と一致することを確認する
